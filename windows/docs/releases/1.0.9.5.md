# Kytto 1.0.9.5 for Windows

**Not yet published.** Unsigned build, same as 1.0.9.4.

User-facing changes are in the repository root `CHANGELOG.md` under `## [1.0.9.5]`.
This file records what was built, what was checked, and what was not.

Ports macOS 1.0.9.5 (`cfc7d0a`): the seven findings of the 2026-11-14 security and
reliability audit (`macos/docs/SECURITY_RELIABILITY_AUDIT_2026-11-14.md`, which checked
macOS only), and roadmap §12, §16, §18 and §20. Every finding was checked on Windows
first; each now has a Windows regression test, whether or not the bug was there.

## Audit findings on Windows

| ID | On Windows before this change | Now |
|---|---|---|
| AUD-07 | **Present, and worse.** `JsonDocument` keeps repeated keys and the filter read them last-wins, so `{"name":"write_file","name":"read_file"}` was approved and forwarded; a first-wins server runs `write_file`. A `tools/call` with a non-string `name`, and any non-JSON line, were forwarded. Windows-only: an id or name with an unpaired surrogate (`"\ud800"`) made `TryGetValue<string>` throw inside the relay callback; the line stayed in the framer's buffer and the shutdown flush forwarded it with everything behind it, unread. Reproduced with the real `kytto-mcp-proxy.exe` and the Python fixture: a hidden `write_file` reached the server. | `GatewayStrictJson` reads each message once, last-wins, decoding names after escapes and reading undecodable text as U+FFFD instead of throwing. On a narrowed route: not JSON → `-32700`, a repeated key at any depth → `-32600`, a `tools/call` without one string `params.name` (or one containing U+FFFD) → `-32602`; batches refuse a non-object element. Refusals echo the raw id when there is exactly one, and are journalled as `(unreadable request)`. Server lines with repeated keys are re-serialized. Tool names compare ordinal. The framer removes a line before handing it on, and the filter never throws. |
| AUD-01 | **Present, without the crash.** `(int)double` saturates in .NET, so nothing threw, but `1e100` read as `int.MaxValue`, `1.5` as `1` and `-32601.5` as "method not found". | `JsonNode.IntegerValue` (finite, integral, fits `int`); `McpHttpClient.ErrorCode` turns anything else into a protocol error, for HTTP 200 and stdio; an HTTP error body with such a code is ignored. |
| AUD-02 | **Partly present.** `Commit` re-checked the digest before each write, but `Prepare` read the digest and the bytes separately, the backup re-read the file, and staging plus the flush to disk sat between the check and `File.Replace`. | One read in `Prepare`; the backup is taken from those bytes (`BackupStore.BackUp(…, snapshot)`); `AtomicWriter.Precondition` re-checks the digest after staging, immediately before `File.Replace`, and an absent target is created with `File.Move(…, overwrite: false)`. A mismatch is `TargetChangedException` → `changedOnDisk`. Backup restore does the same. |
| AUD-03 | **Config files: not present** (`ConfigWriter.RollBack` already restored only files that still held its own bytes). **Parked copies: present** — a failed rotation put the old text back unconditionally. | The rollback write is now also checked at the swap. Parked copies go back only if unchanged; otherwise `SecretsException.RollbackFailed` names them. `ConfigTransactionException` carries the backup ids, and its message names them. |
| AUD-06 | **Not present.** Windows touches Credential Manager only after every config committed, and a credential failure there is not rolled back. | Regression test: a conflict before any credential change leaves the store as it was, with and without "also store". |
| AUD-04 | **Present.** `ManagedProcess.WriteLine` was a blocking pipe write; a 1-second check against a server that sends a 256 KB request id and never reads took **60.1 s** (the fixture's sleep). | `WriteLine(line, deadline)`: the write runs off the calling thread, chained so writes never interleave, and is waited for only until the deadline. A stuck write makes `Terminate` skip closing stdin and kill the job straight away. The test check now ends in about a second, and the server's process is gone. |
| AUD-05 | **Not present.** `MetadataStore.Mutate` calls `KyttoStorage.EnsurePrivateRoot` before the first write, and the file inherits the folder's owner-only ACL. | Regression test from an absent data folder: folder and file private, stderr kept, no staged file left. |

## Features

- **Contract Guard labels** (§18). `ContractSchemaAssessment` is a port of macOS's
  `ContractSchemaAssessment.swift`; `ContractChange` gains `Compatibility`,
  `CompatibilityReason`, `Security`, `SecurityReason`, and `Severity` is derived from them.
  Older stored changes decode with nulls. A schema with repeated keys, or text that
  cannot be decoded, is `unknown` + `review`.
- **Consent-bypass rule** (`ToolRiskKind.ConsentBypass`, warning), with the macOS phrase
  list and negation rule. Doctor title: "the description tells the model not to ask you".
- **Project folders** (§12). Settings → Project folders (folder picker, label, remove,
  files found). Each existing `.mcp.json`, `.cursor\mcp.json`, `.vscode\mcp.json` at the top
  of a chosen folder becomes a synthetic read-only custom source with the macOS
  name-based id (`kytto-project:<FOLDER-UUID>:<file>`); the custom-source reader already
  accepts `mcpServers` or `servers`. Missing files are still watched, so a committed file
  appears without a relaunch. Repository-only servers are left out of Check all, and
  repository paths are protected from portable export like custom sources.
  **Windows goes one step further than macOS:** the matrix's Check visible, which checks
  servers one by one from the page, leaves them out too and says so in its notice. On
  Windows that is the toolbar's main check button, and macOS's Check visible still starts
  them; worth porting back. Found with the real app against an isolated profile
  (`KYTTO_TEST_HOME`/`KYTTO_TEST_DATA_ROOT`) and the probe.
- **Context figure** (§16). `ClientDescriptor.ToolLoading`: Claude Code and Codex
  `deferred`, everything else `unknown`. `ServerDto.toolNameTokens` (cl100k over the known
  tools' names). The client page has the second tile and the source note; the total tile
  reads "tokens if every tool loads".
- **Parked demo reports** (§20). Tool Safety findings after a failed check name the passing
  check they come from (`ServerMetadata.LastPassingCheckedAt`). Add server shows a hint and
  "Remove spaces" for an argument with a leading or trailing space, never trimming it
  itself. Windows re-renders the form on every keystroke, and Chromium fires `change` on
  the input that render removes, so "left the field" is decided after the render from
  where focus actually is (`focusout` and `change` both schedule that look).

## Verified

- `dotnet build` of `KyttoMCP.slnx`: 0 errors. The one warning is WFO0003 from 1.0.9.3's
  `app.manifest`.
- Kytto.Core.Tests: 1293 of 1293 pass. New: `GatewayToolFilterAmbiguityTests`,
  `GatewayLineFramerFailureTests`, an end-to-end test through the real helper
  (`AnAmbiguousCallNeverReachesTheServerAsAHiddenTool`), `ErrorCodeConversionTests`,
  `HealthCheckBoundaryTests` (deadline and private measurements),
  `ConfigWriterConcurrentEditTests`, `RotationRollbackTests`, `ContractLabelTests`,
  `ConsentBypassTests`, `HistoricalFindingTests`, `ProjectFolderTests`, `ToolLoadingTests`.
- Kytto.App.Tests: 275 of 275 pass (run on their own); wire keys for the new DTO fields.
- Web (`npm test`): 135 pass.
- `dev.html` clicked through: Contract Guard labels and reasons, the repository-only note
  on Health, the Claude Code client tiles and note, the Add server hint (hidden while
  typing, shown after Tab, cleared by Remove spaces).
- The Debug app against an isolated profile with one project folder: the repository
  file's column and server appear, and the probe's Check visible checks nothing and says
  why (no `health.check` in `kytto.log`, no measurement written).
