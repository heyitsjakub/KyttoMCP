# Kytto 1.0.6.1 for Windows

A security-hardening release. Kytto's own copies of a client's configuration are
now private to the account that made them, and restoring a backup writes only a
file Kytto manages for that client.

Both findings were low severity and neither was an escalation. This is the
Windows half of the work shipped on macOS as 1.0.6.1, following
[heyitsjakub/KyttoMCP#11](https://github.com/heyitsjakub/KyttoMCP/issues/11).

## Highlights

- **Backups and parked definitions are readable by you and nobody else.** A
  backup is a copy of a whole config, `env` blocks and API keys included, so
  Kytto's data folder, the entire backups tree and the parked-definition store
  now carry a protected access list naming only this account, `SYSTEM` and the
  administrators. Folders are created that way rather than tightened afterwards,
  so a backup is private before it holds a byte — including under its temporary
  name.
- **Anything an earlier version left readable is repaired at startup**, before
  the interface can do anything. It creates nothing, changes only what grants
  access to someone else, and does not follow junctions or symbolic links out of
  the folder it is tidying. A second launch finds nothing to do.
- **A restore writes only a file Kytto manages for that client.** The set of
  destinations comes from the client registry and the path resolver — the same
  data every other write uses — and the write goes to that path rather than to
  the location recorded beside the backup. A backup that no longer matches one is
  refused, with nothing written at all: no pre-restore backup and no temporary
  file. Both the path configured in Settings and the built-in default are
  accepted, so a backup taken before a client's location was moved can still go
  home.
- A configuration the user locked down stays locked down across a Kytto write.
  This already held and is now covered by a test that fails if the write path
  stops preserving it.

## Compatibility and safety

The IPC command, event, request and response shapes are unchanged. One existing
behaviour changed: `backups.restore` can now fail with error code `backup`, and
when it does it writes nothing. The message explains what happened and says the
backup is still in the backups folder. The web layer needed no change — it
already shows that message through its ordinary failure path.

Configuration writes continue through the digest-guarded backup and atomic-write
pipeline, and no secret values reach the web layer or the logs.

Known limitation: a protected access list names this account, which is a local
statement. On a roaming profile or a redirected `%APPDATA%` on a network share,
the share's own permissions decide, and Kytto does not detect either case.
