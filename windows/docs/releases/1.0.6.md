# Kytto 1.0.6 for Windows

Kytto 1.0.6 focuses on making successful configuration changes reliable and
truthful even when a client is being configured for the first time or a
secondary UI refresh fails.

## Highlights

- First-time JSON and TOML configuration creation is now reported as a real
  change even though there were no previous bytes to back up. Idempotent toggles
  create neither backups nor restart requests.
- A Claude Code arrival and its separate deny-list edit commit as one guarded
  transaction. If the second write fails, Kytto restores the exact original
  definition file or removes the newly created file without overwriting a newer
  external edit.
- Profile mutations refuse to replace an unreadable profile store. Optional
  profile maintenance after a server rename no longer turns a committed config
  rename into a reported failure.
- Launch at login now updates the existing per-user Windows integration before
  persisting settings, and restores the previous OS state if settings cannot be
  saved.
- Backups, Profiles and Secrets refresh independently after native mutations.
  A refresh failure keeps the committed state and produces a warning instead of
  reopening a completed form or claiming the original change failed.
- Direct delegated actions now surface native failures as visible notices rather
  than unhandled asynchronous rejections.

## Compatibility and safety

The IPC command, event, request and response shapes are unchanged. Configuration
writes continue through the digest-guarded backup and atomic-write pipeline, and
no secret values are sent to the web layer or logs. Windows update installation
continues to hand replacement to the verified signed Inno Setup package rather
than introducing an app-managed self-replacement mechanism.
