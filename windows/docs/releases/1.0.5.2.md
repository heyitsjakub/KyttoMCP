# Kytto 1.0.5.2 for Windows

Kytto 1.0.5.2 brings the latest macOS behavior fixes to the Windows shell and
shared web interface.

## Highlights

- The sidebar can be resized with a pointer or keyboard, remembers its width,
  and resets to its default on double-click. Claude Code project sources use
  compact but distinguishing labels without losing their full-path context.
- Skill metadata accepts the practical YAML front-matter shapes produced by
  current skills, including literal and folded block scalars, while skill cards
  show their agent and scope only once.
- Long client paths wrap inside the server detail instead of collapsing table
  columns or stacking client names vertically.
- Health failures retain a structured native reason, so their current wording
  is rendered consistently instead of being frozen as stale display text.
- OAuth-backed MCP servers waiting for browser consent now appear in a distinct
  blue Waiting for authorization state. Kytto exposes a validated HTTPS sign-in
  action without accepting a URL from web content, and a later health check can
  replace the waiting state after consent completes.
- Doctor, maintenance provenance, Check all behavior and tray failure counts now
  understand that authorization is waiting for the user rather than unhealthy.

## Compatibility and safety

Older settings files remain valid and receive the default sidebar width. New
DTO fields are additive, project sources remain read-only, skill scans remain
bounded and metadata-only, and OAuth pages are opened only from native health
state after HTTPS validation.

This file describes the source release. Building, signing, packaging and
publishing Windows artifacts remain separate release steps in
[`../release.md`](../release.md).
