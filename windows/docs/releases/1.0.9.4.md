# Kytto 1.0.9.4 for Windows

**Source release 1.0.9.4 · not yet published.** Unsigned build, same as 1.0.9.3.

User-facing changes are in the repository root `CHANGELOG.md` under `## [Unreleased]`.
This file records what was built, what was checked, and what was not.

The theme follows macOS 1.0.9.4 (`8378807`, `3ad6434`): what happens when something Kytto
depends on fails. Windows ships Gateway mode (`gateway.stdio`), so every item applies.

## What changed

- **Contract Guard, old baselines.** A baseline that holds only names and descriptions adopts
  input schemas and annotations from the next check (`ContractGuard.UpgradingLegacyBaseline`,
  applied in `MetadataStore.Record`), so it no longer reports every tool twice.
- **`changedOnDisk`.** `ConfigWriteException.IsChangedOnDisk` gives the refusal its own error
  code. The page decides by code (`isChangedOnDisk`), offers Refresh, and a matrix switch
  offers Try again against the reloaded file.
- **Gateway journal.** `tool.call.refused`, `session.ended` with `unexpected`, and
  `session.failed` with `reason` (`secret-unavailable`, `launch-failed`). The helper marks the
  client as gone before it closes the server's input. The reader fills the view from
  `gateway-events.jsonl.1` right after a rotation. `Raw(GatewayEventKind)` used to map every
  unknown kind to `session.ended`; it names the new kinds now.
- **Gateway Doctor.** `GatewayMigrationService.Diagnose` (configs and the route file only,
  never Credential Manager) and `GatewayDoctor.Findings` (plus the last 24 hours of the
  journal) give `gateway-helper-missing`, `gateway-route-unknown`,
  `gateway-secret-unavailable`, `gateway-launch-failed` and `gateway-server-stopped`.
- **Repair route** (`gateway.repair`, capability `gateway.repair`). On Windows "moved" means
  Kytto was reinstalled in another folder or a portable copy was run from elsewhere. Refused
  while Kytto runs from a ZIP's temporary extraction.
- **Restore Direct mode for all** (`gateway.restoreAll`) in MCP Doctor. The uninstaller
  (`scripts/installer.iss`, `InitializeUninstall`) warns when `gateway-routes.json` still has
  routes; the prompt is suppressible, so a silent uninstall goes ahead.
- **Restore Direct without the stored original** rebuilds the definition from the route and
  names what it could not recover (`missingEnvironmentKeys`).
- **Secret rotation reaches the routes** and the stored original. The client's config does
  not change, so a rotated route secret is counted in the restart snapshot
  (`@gateway-secret:<route>`) to raise the restart notice.
- **Restart now verifies** (`restarts.restart` → `verify`), computed by
  `AppModel.ServersAwaitingRestart` before the acknowledgement.
- **Profiles: Undo and Try again** (`profiles.apply` → `applied`, new `profiles.revertApply`).
- **Client screen line.** The three `.client-servers` rules from macOS `3ad6434`; the Windows
  client screen uses the same `matrix client-servers` table and showed the same line.

## Verified

- `dotnet build` of `KyttoMCP.slnx`: 0 errors. One warning, WFO0003 about the DPI settings in
  `app.manifest`, which 1.0.9.3 added; nothing here touches the manifest.
- Kytto.Core.Tests: 1155 of 1155 pass. New: `GatewayReliabilityTests` (20 — moved Kytto for
  JSON and TOML, repair behind the digest guard, unknown route, restore without the
  original, lost value named, rotation into route and stored original, TOML env in all three
  spellings, Doctor findings, summary counts, old journal lines, reading across rotation,
  hidden-call names), three legacy-baseline tests in `ContractFieldDiffTests`, and four
  end-to-end journal tests against the real `kytto-mcp-proxy.exe` (refusal, crash, clean
  close, launch failure).
- Kytto.App.Tests: all pass (run on their own, not alongside Core). New:
  `GatewayRecoveryIntegrationTests` (Doctor finding → Repair route; Restore all with a lost
  original and value), profile apply undo, `changedOnDisk` code, wire keys for the new DTO
  fields.
- Web (`npm test`): all pass; `ui-contract.test.js` checks every new command has an
  `ipc.md` row.
- `installer.iss` compiles with ISCC 6 against a placeholder payload.
- macOS's stale `checkAllBatchesDiscovery` assertion has no Windows counterpart.

## Not verified

- Restart now with the post-restart check against real clients (it would quit real apps).
- Secret rotation and Restore Direct through the real Credential Manager; covered by tests
  with an in-memory store.
- The uninstaller prompt in a real uninstall.
- Installer build and SHA-256. Not built for this draft.
