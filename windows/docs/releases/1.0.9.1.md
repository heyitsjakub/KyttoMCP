# Kytto 1.0.9.1 for Windows

**Source release 1.0.9.1 · 2 November 2026.** The public release includes an unsigned
Windows x64 Inno Setup installer, built with `scripts/release.ps1` from commit
`b5a5aee` (SHA-256 `965c6babf1a5241031db527e80927c55faad98bd85b4ab2bf3d39a56e23703f2`);
it was not installed on a clean profile before publishing.
This release ports the macOS 1.0.9.1 work (macOS commit `63730d2`): three new
clients, switches for single tools, a package safety check in MCP Doctor, and a
steadier window. Each item was first checked against the Windows code. The
user-facing list is in the repository root `CHANGELOG.md` under `## [1.0.9.1]`; this
file records what was ported, what Windows already had and what stays unverified.

## What is new

- **Antigravity, Devin Desktop, OpenCode.** The per-server shape is data on the
  descriptor (`ServerSchema`). Antigravity: `serverUrl`, no `type`, Streamable HTTP
  only. Devin Desktop: `url`, `transport: "sse"` only for the legacy transport.
  OpenCode: `type: local|remote`, one `command` array, `environment`; a transport
  change removes the other kind's keys and a remote entry never gets `environment`.
  Copies between `mcpServers`-shaped clients respell only the keys the two disagree
  on and drop the source client's own `disabled`/`enabled`/`disabledTools`/
  `enabledTools`; copies into or out of OpenCode are rendered from the model and
  refused, naming the settings, when they would drop `headers`, `cwd`, `envFile` or
  `oauth`. A JSON inline flag (`InlineDisabledFlag` / `InlineFlag`) turns a server
  off without parking anything. Portable import writes the off flag on the entry,
  secret rotation writes under `environment` for OpenCode, the Doctor pin edits
  `command[index + 1]`, Gateway mode refuses OpenCode, and remote checks expand
  `{env:VAR}` as well as `${VAR}`.
- **Single-tool switches** (`ToolSwitch`, `ToolFilter`, `ToolSwitchService`):
  Claude Code `permissions.deny`, Codex `disabled_tools`/`enabled_tools`,
  Antigravity `disabledTools`/`enabledTools`, OpenCode's `tools` map. Globs and
  whole-server rules lock tools; switching on under a broader OpenCode `false` writes
  the tool's own `true`; Claude Code refuses naming the broader rule. The lock map is
  built tolerating a tool name listed twice, and renaming a server renames OpenCode
  `tools` keys and Claude Code `mcp__…` rules in the same transaction without
  touching a server whose name merely starts the same way. A tool switch counts as
  a pending restart. New command `servers.setDisabledTools`; new fields
  `toolSwitchSummary`, `toolsOff`, `lockedTools`.
- **Package safety** (`PackageSafety`, `PackageSafetyLookup`): the offline look-alike
  check always runs; `doctor.checkPackageSafety` (capability `package-safety`) asks
  osv.dev and, for npm, the registry's version document, only on a click. 10 s
  timeout, 4 MB cap, no redirects, the answer must come from the address asked.
- **Speed and stability.** Watcher events and Refresh run discovery on a worker and
  apply it on the UI thread (`AppModel.Reload.cs`); the digests a pass saw are
  adopted only when it is applied, and a pass that overlapped a write is discarded and
  run again. The page is told only when something it shows differs. The Gateway
  route store is read once per reload and once per state reply, and the Secrets scan
  asks `git check-ignore` once per file.

## Already correct on Windows

`~/.claude.json` was already read and parsed once per discovery pass (the project
scopes are walked from the same parsed document), so the macOS per-project re-parse
did not exist here and no read cache was added. Plugin text files were already read
once each per pass.

## Windows-specific translations

- Install detection for the three new apps uses per-user install paths under
  `%LOCALAPPDATA%\Programs` and the executable names `agy`/`antigravity`,
  `devin`/`windsurf` and `opencode` (`.cmd`, `.exe`). A missing app only changes the
  "installed" label, and a client that is not installed gets the drawn placeholder
  icon like any other.
- `{env:VAR}` / `${VAR}` expansion, `%USERPROFILE%`-style paths and the `\` in
  displayed paths follow the existing Windows resolver.

## Verification

Run on Windows 11 with the .NET 10 SDK, from this source tree:

| Check | Result |
| --- | --- |
| `dotnet build` | 0 warnings, 0 errors |
| `dotnet test` | **1105 Core + 255 App tests passed** (1.0.9: 1040 + 251) |
| `npm test` (web) | **132 passed** |

New tests cover each ported item: the three clients (discovery, flag toggles,
authoring, copies in both directions, SSE refusal, portable import, secret rotation,
Gateway refusal, `{env:VAR}`), the tool rules and writes for all four clients
(including rename and the broader-rule cases), package look-alikes, OSV and npm
parsing and the lookup over a recording handler, Git asked once per file, and the
background reload (no-op pass, real change, ledger adoption). The tool picker and its
Undo notice were also exercised in `web/dev.html`. Tests use temporary homes and
in-memory secret stores; nothing wrote to a real client configuration or to
Credential Manager.

## Not verified

- None of Antigravity, Devin Desktop or OpenCode is installed here: their Windows
  config paths, install locations and executable names follow the clients'
  documentation, not a real install. OpenCode's wildcard precedence in `tools`,
  Claude Code's glob support inside deny rules, and the desktop bundle/install
  locations of Devin Desktop and OpenCode are unconfirmed on both platforms.
- OpenCode's top-level `tools` map is marked deprecated in its schema; it still works.
- Workspace and project configs of the three new clients are not read.
- A real osv.dev / npm registry round trip (the macOS check against
  `mcp-server-github` was not repeated on Windows), the background reload under a
  real Claude Code session, the installer, signing and the clean-profile smoke run in
  `docs/release.md`.
- The installer was built but not run, and nothing was installed on a clean profile.

## Compatibility

New command `servers.setDisabledTools` and `doctor.checkPackageSafety`; new client
fields `toolSwitchSummary` and server fields `toolsOff`, `lockedTools`,
`packageSafety`; the capability `package-safety`; `DoctorFinding.action` may be
`checkPackageSafety`. All are documented in `docs/ipc.md`. The Windows updater needs
the Windows entry in the website manifest bumped to 1.0.9.1 (tag `v1.0.9.1-windows`,
asset `Kytto-Setup-win-x64-1.0.9.1.exe`) before it offers the update; the updater's
User-Agent must not contain `CFNetwork` or `Darwin`.
