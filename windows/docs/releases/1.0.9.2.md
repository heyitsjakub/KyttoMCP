# Kytto 1.0.9.2 for Windows

**Source release 1.0.9.2 · 5 November 2026.** This release ports macOS 1.0.9.2
(macOS commit `d397db2`): MCP Doctor stops recommending archived reference servers
and flags them where they are already in use. The user-facing list is in the
repository root `CHANGELOG.md` under `## [1.0.9.2]`; this file records what was
ported and what stays unverified.

## What is new

- **Archived reference servers** (`PackageSafety.ArchivedNpm`, `ArchivedPyPi`,
  `IsArchivedReference`). The eleven npm servers the MCP project moved to
  `modelcontextprotocol/servers-archived` and the PyPI `mcp-server-sentry`,
  `mcp-server-sqlite` and `mcp-server-aws-kb-retrieval` get an offline
  `archived-package` warning carrying the `checkPackageSafety` action. A PyPI name is
  compared after PEP 503 normalisation. The packages stay in the official lists,
  because imitations of them still circulate.
- **npm deprecation** (`PackageSafety.DeprecationFromNpmVersion`). "Check package
  safety" reads `deprecated` from the npm version document it already fetched for
  install scripts — no new request. A string is trimmed and cut to 300 characters
  (never inside a surrogate pair), an empty one reads as "deprecated", `false` or a
  missing field is not deprecation. The result is a `deprecated-package` warning,
  left out for an archived package so it is not reported twice.
  `PackageSafetyReport.Deprecation` and `PackageSafetyDto.Deprecated` (wire key
  `deprecated`) carry the message.
- **Look-alike advice.** When the official package a name imitates is itself
  archived, the warning no longer says "change the command to …" and points to a
  maintained server instead.

`docs/ipc.md` documents the new findings and the `deprecated` field. The web layer
needs no change: the findings render through the existing Doctor list, and the
server details summary is the same as on macOS.

## Verification

Run on Windows 11 with the .NET 10 SDK, from this source tree:

| Check | Result |
| --- | --- |
| `dotnet build` | 0 warnings, 0 errors |
| `dotnet test` | **1118 Core + 256 App tests passed** (1.0.9.1: 1105 + 255) |
| `npm test` (web) | **132 passed** |

New tests cover the archived list (npm, a pinned version, PyPI with a differently
spelled name), maintained reference servers left alone, the look-alike advice for an
archived and a live official package, the deprecation parser (string, `false`,
missing, blank, over-long, not an object), the deprecated finding and its suppression
for an archived package, the lookup carrying the message over a recording handler,
and the wire keys of `PackageSafetyDto`. The existing test that edited a server to
`@modelcontextprotocol/server-github` now uses `server-filesystem`, as on macOS,
since the former is archived.

The live npm registry was asked once by hand: `@modelcontextprotocol/server-github`
`latest` (2025.4.8) carries a `deprecated` string and
`@modelcontextprotocol/server-filesystem` `latest` carries none, which is the shape the
parser reads.

Timing-sensitive Core tests (loopback servers, watchers, process spawns) failed under
load when the Core and App suites ran at the same time; each passed when run on its
own, and none touches package safety.

## Not verified

- The full lookup in the running app against live osv.dev and the npm registry, and
  the Doctor screen showing the new warnings in a WebView2 window.
- The installer, signing and the clean-profile smoke run in `docs/release.md`.

## Compatibility

`PackageSafetyDto` gains `deprecated` (string or null); Doctor findings may carry the
codes `archived-package` and `deprecated-package`. Nothing else on the wire changed.
The Windows updater needs the Windows entry in the website manifest bumped to 1.0.9.2
(tag `v1.0.9.2-windows`).
